# 分析约定：生成前冻结

2026-09-17｜analysis-1.0｜以方案 0.3 和应用 0.2.1 事件为依据。先写本文件和 config.json，再执行小案例与完整生成；不根据结果调到理想转化率。

本目录只有 simulated 练习数据，原 81 条 demo 日志仅用于核对字段与顺序，不复制进分析样本。没有真实患者资料、真实行为推断或临床结论。

## 规模与假设

固定随机种子 20260917，400 名虚拟使用者，2026-06-01 起 90 个自然日，Asia/Shanghai 分日；窗口结束为 2026-08-30 00:00（不含），最后一个观察日为 8 月 29 日。进入日期均匀分散到整个窗口，保留观察不足者。规模适合个人电脑运行，90 天使 7/30 日完整窗口与截尾都出现；不是医学使用频次建议。

参数完整值保存在 config.json。每个使用者以固定的独立随机流生成：40% 的“高缺项倾向”只是生成器设定；该组草稿概率 0.28、另一组 0.08，日期/时间/情境缺项概率也分别给定。新记录内容仅生成状态与关联所需的虚构元数据，不生成具体血糖值或自由文字。unknown_count 是五类可未知字段的合计，分析不拆字段。

首次开始录入概率 0.92。后续每天是否出现一次会话以 max(0.025, 0.13×exp(-已进入天数/70)) 抽样；会话中新增概率 0.65、已有记录时编辑概率 0.24，其余允许只展示历史。低缺项组进入核对概率 0.90，高缺项组人为减 0.10；核对后请求保存概率 0.92。保存失败概率 0.10，失败后同一次尝试重试概率 0.70，最多一次重试。草稿补全概率 0.72。核对重复概率 0.15，不重复制造成功。以上全部是教学假设，不来自患者或 demo 的概率估计。

60% 被设为可能有复诊准备机会；第一次在进入后 7—28 天，之后相隔 14—28 天。落在观察期外的机会不算已观察到的机会。机会日开始准备概率 0.75，有机会设定的回访会话另有 0.01 的随时准备概率；其他使用者仍可记录或看历史。**机会表、缺项倾向等单独保存在 simulation_truth.json，只用于理解模拟机制，不是产品新增的埋点，不混入常规分群。**

准备时选当前已有记录：35% 不限日期，否则选择当日及向前 14 天；45% 主动纳入日期未知；范围内每条被选概率 0.90。选中草稿不计有效数，至少一条有效记录才能生成。发起生成概率 0.86；额外普通故障概率 0.08，明确开发测试注入概率 0.03，普通重试与注入后的简版回退概率 0.70。本人确认概率 0.82；复制、页面预览及打印请求分别抽样，绝不生成打印成功事件。参数不与预设结论绑定。

同一记录有独立 id 与连续修改版本。摘要保存选取范围、候选库 id、采用的记录版本。原记录修改、新记录进入原范围、新日期未知记录及同次准备产生新摘要时，按现有应用规则使旧材料失效；同一记录可用于不同准备。只对存在的摘要展示/确认/取用，失效版本不能确认或取用。模拟中不清空/重置账号、不模拟所有浏览器并发/容量情形；这些是范围限制。

执行后补记的生成器限制（未更改冻结参数）：同一次即时生成重试不改变选择，因此没有有效记录时仍失败；没有成功生成过摘要的准备，未模拟之后回到同任务重新选取。普通生成失败恢复率受此结构影响，不能推广为产品恢复能力。本次草稿只模拟数值或单位其中一项缺失，没有穷尽两项同时缺失；编辑时可减少未知合计，但不推断具体哪个字段已补全。

操作时间按模拟会话实际顺序递增，保存时间与测量日期独立；补录日期最多向前 7 天，不据此增加使用天数。重复核对/展示有不同 event_id，是重复操作；数据质量注入的相同 event_id 则是重复行，二者分开。

## 数据文件及质量注入

每个情景写入自己的 raw 子目录：events.jsonl 为原始行为日志；record_versions、preps、summaries 为模拟业务关系表；simulation_truth 保存不可被产品直接观测的生成设定。事件字段只采用当前白名单，data_kind=simulated；没有阅读时长、退出原因、主动查历史意图或医学数据。

数据质量练习采用追加坏行后打乱顺序：追加约 1.5% 完全重复事件，再加 12 行无效时间、8 行缺使用者、8 行悬空记录关联。原有效事件保留，注入账本单独保存。清洗只使用字段/业务约束，不读取账本来猜修复值；去重、隔离坏行、排序，不补造事件。由于原业务链没有被破坏，这个练习较理想，不能证明真实缺日志也可无损恢复。产品保存失败或生成失败是正常分析数据，不能当脏数据删除。

## 指标先定义，后计算

| 分析 | 对象、分子与分母 | 窗口与限制 |
| --- | --- | --- |
| 新增漏斗 | 去重 attempt_id：开始→核对→请求→任意保存→有效保存；每层报尝试数及相对所有开始的比例 | 有效保存与草稿保存并列解释；后续编辑补全不回填到原新增成功。单纯打开页面不入分母 |
| 编辑与补全 | 编辑尝试有效保存／编辑开始；首次为草稿的 record_id 后来转 valid／首次草稿记录 | 是观察期内结果；窗口末尾草稿机会不足另以至少 7 天可观察记录作补充，不把未知强填当改善 |
| 准备任务漏斗 | prep_id：开始→请求生成→至少一次成功→至少一次确认→可选取用 | 曾完成与期末有当前有效确认版本分别报。确认不是医学审核 |
| 摘要版本漏斗 | 同一 summary_id：成功→展示→确认→复制成功/打印请求 | 不拼接 v1 展示和 v2 确认。展示不证明阅读，打印请求不证明打印 |
| 回访 | 首次手动 valid 保存所在本地日为 D0；D1、D1—7、D1—30 内回来的使用者／有完整窗口的首条有效使用者 | 分保存记录（含编辑/草稿）、有效新增、历史展示、开始准备、完成准备五类，允许重叠。D0 不算回访；不足窗口排除并报告人数 |
| 有效新增回访 | 窗口内 mode=create、status=valid 且不同于首条有效记录的 record_id | 草稿补全属于编辑，可算保存回访，不能冒充新增。history_viewed 含自动跳转，只称历史展示 |
| 失败恢复 | 失败后同 attempt_id 成功／失败尝试；失败后同 prep_id 后续成功／失败准备任务 | 普通和显式测试注入分开；最多一次即时重试是生成假设，不是产品限制 |
| 信息质量与负担 | 首次核对 unknown_count 的 0—1/2—5 分组；保存状态、草稿转有效、核对次数、重试、每任务摘要版本数、来源展示率 | 没有首次核对者未知组单列。只看总缺项，不拆字段；事件间隔不是精确活动耗时，不推断退出原因 |

业务有意义的分群优先采用可观察的首次/后续新增尝试、首次核对缺项总数与是否遇到保存失败。生成器“高缺项倾向”和“有无机会”不作为网页已观测画像；机会仅另列模拟解释，不能推广到真实用户。

参数变化只预先指定两次：daily_return_probability 从 0.13 降至 0.07；save_failure_probability 从 0.10 升至 0.20。其他参数和种子保持，使用相同规模观察窗。随机路径可能随行为分支变化，并非真实对照试验；不反复调参，不声称优化收益。图表推荐四幅：两流程漏斗、分类回访、缺项分组结果、失败与恢复；敏感性用紧凑表。
